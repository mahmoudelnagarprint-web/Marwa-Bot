# نظام الذاكرة

## الفكرة
الذاكرة ملفات نصية هنا. ما لا يُكتب هنا يضيع بانتهاء المحادثة. ولك حرية كاملة في تنظيمها (مستوى 0).

## الهيكل
- owner_preferences.md: طريقة تعامل المالك وتفضيلاته وأسلوبه في اتخاذ القرار.
- clients_notes.md: ملاحظات سلوكية عن العملاء (التزام بالدفع، نوعية الطلبات، تفضيلات). لا تنسخ بيانات العملاء الأساسية من البرنامج.
- products_notes.md: ملاحظات الأصناف والخامات والحركة والموردين.
- orders_notes.md: ملاحظات الطلبات والملخصات والأنماط.
- decisions_log.md: سجل زمني لكل قرار وتعديل في الذاكرة أو القواعد، ولماذا.
- telegram-house.md: فحص وخيارات بيت تيليجرام (elnagarprint مقابل dsh-bridge) — قرار المالك المعتمد 2026-10-12: الاكتفاء بـelnagarprint، ولا بوت تيليجرام في dsh-bridge.
- roadmap.md: خارطة التطوير والمراحل وشرط العبور لكل مرحلة والحالة الحالية.
- lessons.md: أخطاء وتصحيحات ودروس.
- open_questions.md: أسئلة معلّقة للمالك أو للتحقق.
- reports/: تقارير دورية (تسمية: YYYY-MM-DD_weekly.md).
- archive/: ما قُدّم أو انتهت صلاحيته. لا حذف نهائي من الذاكرة؛ انقل للأرشيف.

## صيغة الإدخال
- [YYYY-MM-DD] [المصدر: البرنامج | المالك | استنتاج] [الثقة: عالية | متوسطة | منخفضة] النص
استخدم التاريخ الفعلي من النظام.

## قواعد التنظيم
- ملف يتجاوز نحو 300 سطر: قسّمه حسب الموضوع أو العميل أو الفترة، وحدّث هذا الفهرس.
- اكتشاف تكرار أو تناقض: ادمج، وسجّل في decisions_log.md.
- معلومة قديمة غير مؤكدة: خفّض ثقتها أو انقلها للأرشيف بدل حذفها.
- أنشئ ملفات جديدة متى احتجت (مثل suppliers.md أو seasonality.md)، وأضفها للفهرس هنا.
- المرجع دائمًا هو البرنامج. لا تنسخ عملاء أو طلبات كاملة هنا؛ اكتب الملخصات والأنماط والملاحظات.
- ممنوع تخزين أسرار أو مفاتيح أو كلمات مرور.

## المراجعة الدورية
مرة أسبوعيًا (أو عند طلب المالك أو أول جلسة بعد أسبوع): راجع الذاكرة، لخّص، دمج، أرشف، حدّث الثقة، وأنشئ تقريرًا في reports/.
